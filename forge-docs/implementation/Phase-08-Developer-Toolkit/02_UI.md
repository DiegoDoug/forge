## 1. Screens / views

One screen, replacing three existing ones:

- **`/developer-toolkit`** (new URL) — the unified Developer Toolkit page. Top-level `Tabs` (the same shadcn/ui `Tabs` primitive already used on the current Crypto page), one per consolidated area:
  - **Generators** — the existing grid of 7 components (`PasswordGenerator`, `UuidGenerator`, `NanoIdGenerator`, `RandomBytesGenerator`, `ApiKeyGenerator`, `JwtSecretGenerator`, `EntropyEstimator`), moved here unmodified from today's `/generators` page.
  - **Crypto** — the existing page's own nested `Tabs` (Encode & Hash / AES / JWT / RSA & ECC), moved here unmodified from today's `/crypto` page, nested one level inside the new top-level Crypto tab.
  - **Utilities** — the existing grid of 4 components (`QrTool`, `ColorTool`, `TimezoneTool`, `ChecksumTool`), moved here unmodified from today's `/utilities` page.

  **Rationale for top-level tabs, not Universal Converter's stacked-section layout:** Universal Converter's two sections (Text & Data, Documents) were both flat grids with no internal tab structure, so stacking them on one scrolling page introduced no new UI paradigm. Developer Toolkit's Crypto section is *already* internally tabbed — stacking three sections where one is itself tabbed would either bury two tab levels inside a long scroll or read inconsistently (two sections as plain grids, one as a nested tab set, all stacked). Top-level tabs give each of the three areas equal visual weight and let Crypto's existing nested tabs sit at a natural second level, matching how the current Crypto page already handles this without a redesign. **Confirmed by the project owner 2026-08-05** — the stacked-section alternative was explicitly offered and declined; see [`01_SPEC.md`](01_SPEC.md) §7.

- **`/generators`, `/crypto`, `/utilities`** — each becomes a redirect to `/developer-toolkit?tab=<name>`, per [`01_SPEC.md`](01_SPEC.md) §3 requirement 2. None is a real screen after this phase ships.

## 2. Navigation

`frontend/lib/nav-registry.ts` currently has three entries:

```ts
{ title: "Generators", href: "/generators", icon: Wand2, description: "Passwords, UUIDs, keys", shortcut: "G" },
{ title: "Crypto", href: "/crypto", icon: ShieldHalf, description: "Encrypt, hash, sign, JWT", shortcut: "C" },
{ title: "Utilities", href: "/utilities", icon: Wrench, description: "QR, checksums, timezones", shortcut: "U" },
```

These are replaced by one entry:

```ts
{ title: "Developer Toolkit", href: "/developer-toolkit", icon: Wrench, description: "Generators, crypto, and utilities", shortcut: "U" },
```

- **Icon (confirmed 2026-08-05):** keep `Wrench` (Utilities' current icon — reads most generically as "toolkit" of the three) and free `Wand2`/`ShieldHalf` for future use.
- **Shortcut (confirmed 2026-08-05):** keep `U` (Utilities' current shortcut) and free `G`/`C`. An alternative `D` ("Developer") was offered and declined — `D` currently belongs to Workbench and would have required a reassignment.
- **Route and label (confirmed 2026-08-05):** `/developer-toolkit` and "Developer Toolkit", matching the phase's own name and the kebab-case slug pattern of `/project-init`, `/prompt-studio`, `/model-playground`. A shorter `/toolkit` slug was offered and declined.
- The command palette (`cmdk`) reads from the same `NAV_ITEMS` registry, so this one change updates both surfaces per [`04_UI_GUIDELINES.md`](../../04_UI_GUIDELINES.md) §2.
- `frontend/features/workbench/components/quick-actions-panel.tsx`'s "Generate password" quick action updates its href to `/developer-toolkit?tab=generators` (see [`01_SPEC.md`](01_SPEC.md) §3 requirement 5).
- `frontend/features/workbench/tool-metadata.ts`'s `NAV_KEY_BY_HREF` map collapses its three entries (`/generators`, `/crypto`, `/utilities`) into one (`/developer-toolkit` → `developer_toolkit`), mirroring `WORKBENCH_TOOL_KEYS`'s backend-side merge ([`01_SPEC.md`](01_SPEC.md) §3 requirement 4).

## 3. States

**Generators tab** — unchanged from today; each generator component already defines its own trigger/output/copy-confirmation states inline. No new state work required — components are moved, not rebuilt.

**Crypto tab** — unchanged from today; the existing nested `Tabs` and each tool's own success/error/loading handling (e.g. JWT decode failure, AES decrypt failure) is inherited unmodified.

**Utilities tab** — unchanged from today; each tool (QR render, checksum compute, color convert, timezone convert) already handles its own empty/populated/error states client-side (e.g. `ChecksumTool`'s hashing-in-progress state via local `useState`).

No new state design work is required by this phase — all three sections' state handling is inherited unmodified. Called out explicitly, rather than left silent, per [`04_UI_GUIDELINES.md`](../../04_UI_GUIDELINES.md) §5's requirement that every list-based/data-dense feature's phase doc state this even when the answer is "already covered" — matching Universal Converter's `02_UI.md` §3 precedent for the same situation.

## 4. Responsive behavior

Unchanged from today at the component level: the Generators and Utilities grids already collapse from `md:grid-cols-2` to a single column below the `md` breakpoint; the Crypto page's tabs and per-tab grids are already responsive. The one new responsive concern this phase introduces is the **top-level tab bar** itself at narrow widths — the existing shadcn/ui `Tabs` primitive (already used on the Crypto page today) already handles this via horizontal scroll/wrap, so no new responsive pattern is being invented, only reused one level up.

## 5. Accessibility

Unchanged from today for each section's internal controls — no new interactive pattern is introduced there. The two net-new interactive elements are:
- The single consolidated nav entry — reuses the existing sidebar/command-palette keyboard navigation path unmodified.
- The new top-level `Tabs` — reuses the same shadcn/ui `Tabs` primitive (Base UI-backed, WAI-ARIA `tablist`/`tab`/`tabpanel` roles, arrow-key navigation) already shipped and in use on the current Crypto page, so no new accessibility pattern is being designed, only nested one level deeper.
