## First RC Run (2026-08-04)

The FDK Verification Framework was invoked for the first time against a real phase: `run_release_candidate_check()`, 3 repair cycles, **overall FAIL**. Full detail: `forge-docs/history/2026-08-04-phase-07-verification-report.md` and the companion `-verification-escalation.md` — preserved as-is, not rewritten by this reconciliation.

**No Knowledge Hub implementation defect was found.** Every FAIL traced to one of:

1. **Specification FAIL (all 16 tasks / 41 criteria "not complete")** — the RC pipeline reads completion state from `VERIFICATION_CONTRACT.md`'s own §2/§3 checkboxes, not from `09_IMPLEMENTATION_TASKS.md`/`08_ACCEPTANCE.md` (which *were* checked off at implementation time). The contract's own copies were never synced. **This reconciliation task fixed that** — see Completed, below — while also discovering that 2 of the 41 criteria (AC34, AC39) and 3 of the 9 regression targets genuinely cannot be checked off yet (see next point), so the sync is now honest, not a blanket 41/41.
2. **Regression FAIL (all 9 targets "not confirmed")** — same root cause: contract §8 checkboxes were never set. On review during this reconciliation, 6 of 9 have real evidence (Ingest, Search, Workbench, Projects, App shell, migration chain) and are now checked; 3 (Notes edit/pin/archive, Documents rich-text/export/history, Activity logging) do not have direct evidence in this phase's test/QA trail and are deliberately left unchecked rather than assumed.
3. **Documentation FAIL (4 of 7 requirements "not found")** — `10_RELEASE_NOTES.md` was a genuine gap, now fixed (see Completed). `docs/Architecture.md`'s requirement is conditional ("if the consolidation changes a documented boundary") and the Documentation Verifier cannot evaluate conditionals — reviewed this session; no boundary changes, so the requirement itself is now correctly marked not-required in the contract, not silently ignored. `02_ROADMAP.md`/`implementation/README.md` surface a genuine, still-open governance question — see Known Issues.
4. **Architecture FAIL** — a self-inflicted artifact: the RC pipeline's own report-persistence step writes into `forge-docs/history/`, which this (and presumably every) phase's contract declares out-of-scope, so re-running the pipeline within one session flags its own prior report as an out-of-scope change. Not a Phase 07 defect. Framework-level, not touched here.
5. **Test FAIL** — both declared §5 commands failed with `'backend' is not recognized as an internal or external command`. Root cause confirmed: `tools/fdk_verification/verifiers/_shell.py` uses `subprocess.run(shell=True)`, which resolves to Windows `cmd.exe`, and `cmd.exe` does not resolve a leading relative executable path written with forward slashes (`backend/.venv/Scripts/python.exe`) the way Git Bash does — the same command with backslashes, or run via Git Bash directly, succeeds. Independently confirmed the actual suites pass (292/292, 87/87) via Git Bash both before and after this discovery. Environmental, not a test failure. Framework-level, not touched here.
6. **Code Quality** (never fails by design, warnings only) — mostly substring false positives on the word "TODO" appearing in prose, plus warnings on the pipeline's own persisted report files from a re-run. Framework-level, not touched here.

Items 4–6 (plus item 3's conditional-evaluation limitation) were recorded as framework-hardening candidates — see "Evidence-Gap Closure" below for their resolution in a dedicated follow-up task.
