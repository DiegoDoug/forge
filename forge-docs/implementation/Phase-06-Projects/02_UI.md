# Projects — UI

> **Purpose:** Screen-level and interaction-level UI specification for this phase.
> **Scope:** UI/UX only. Component implementation detail lives in 05_COMPONENTS.md; general UI conventions live in the root UI guidelines.
> **Ownership:** Project owner (confirmed 2026-08-02)
> **Status:** Confirmed
> **Last Updated:** 2026-08-02

---

## 1. Screens / views

- **`/projects`** — Project list. Grid/list of project cards (name, color swatch, archived badge if applicable, secret/note/document counts), a "New Project" button, an archived-toggle filter. Same layout family as `/secrets`' list+filter bar.
- **`/projects/[id]`** — Project detail/workspace. Sections: header (name, description, color, edit/archive/delete actions), AI configuration (provider/model picker + "configured" status + quick-run prompt box + recent AI activity list), and three scoped lists (Secrets / Notes / Documents belonging to this project, each a compact list linking into the existing `/secrets`, `/notes`, `/documents` pages filtered to this project).
- **Modifications to existing screens** (additive only):
  - `/secrets`, `/notes`, `/documents`: each list view gains a project filter control alongside its existing filters, and each create/edit form gains an optional project picker field.
  - Workbench (`/`): gains a "Recent Projects" panel in the panel catalog (opt-in via customize mode, same as every other panel).

## 2. Navigation

- Sidebar: new entry "Projects" in `NAV_ITEMS` (`frontend/lib/nav-registry.ts`), positioned after "Documents" and before "Generators" (grouping with the other persistent-data features: Secrets/Notes/Documents/Projects, ahead of the tool features), with a `FolderKanban`-style icon and a keyboard shortcut letter not already taken (`P`).
- Command palette: automatically reachable — the palette is driven by `NAV_ITEMS`, so no separate registration is needed (verified against existing palette implementation before building).
- Project detail links: `/secrets?project=<id>`, `/notes?project=<id>`, `/documents?project=<id>` deep-link from the Project page into each feature's filtered view, following the same `?open=<id>` / `?new=1` deep-link convention Secrets/Notes already use.

## 3. States

**Project list (`/projects`)**
- [x] Empty: `EmptyState` component, "No projects yet" + "New Project" action (matches `RecentNotesPanel`'s empty-state pattern).
- [x] Loading: skeleton cards (`Skeleton`), same count/shape convention as `SecretsPage`.
- [x] Error: inline message + retry button (TanStack Query `isError` + `refetch`).
- [x] Populated: project cards grid.

**Project detail (`/projects/[id]`)**
- [x] Empty: n/a for the page itself, but each of the three scoped lists (Secrets/Notes/Documents) has its own empty state ("No secrets in this project yet" + link to create one pre-filled with this project).
- [x] Loading: skeleton for header + each section independently (sections load in parallel, don't block on each other).
- [x] Error: not-found state (project deleted or bad ID) renders a dedicated "Project not found" panel with a link back to `/projects`, distinct from a generic error/retry (matches how Model Playground's `useRun(id)` handles a missing run).
- [x] Populated: full workspace view.

**AI configuration section**
- [x] Empty/unconfigured: "No default provider set" + picker.
- [x] Configured but credential missing: picker shows the provider as selected but flags "not configured" (reusing `ProviderAvailability.configured`), quick-run box shows a disabled state with a link to Model Playground's credential settings.
- [x] Configured and ready: quick-run box active; submitting shows a loading state (matches `RunView`'s in-flight state) then the result inline.
- [x] Error: run failure (timeout/provider error) renders inline using the same `status`/`error_message` shape Model Playground's `ResultPanel` already renders — reused component, not reimplemented.

(Required per `../../04_UI_GUIDELINES.md` §5.)

## 4. Responsive behavior

- Project list: card grid collapses to a single column at mobile widths (same breakpoint convention as the existing dashboard/secrets grids).
- Project detail: the three scoped-list sections and the AI panel stack vertically at mobile widths instead of the desktop multi-column layout (same `grid-cols-1 ... lg:grid-cols-[...]` pattern `ModelPlaygroundPage` already uses).

## 5. Accessibility

- Project picker (a `Select`), AI provider/model pickers, and the quick-run textarea are all standard shadcn/Base UI primitives already used elsewhere (`Select`, `Textarea`) — keyboard nav is inherited, not custom-built.
- Delete confirmation is a `Dialog` (not a bare `confirm()`), reachable and dismissible via keyboard, consistent with `04_UI_GUIDELINES.md` §2's "destructive actions require a confirmation step."
- Color swatch picker uses labelled, focusable swatch buttons (not a bare `<input type=color>` with no label), matching how Tag colors are edited today.
