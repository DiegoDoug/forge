## 0. Layout invariants — frozen before T1

Added at the project owner's direction, 2026-08-06, before the token system lands.

These are **structural constraints, not tokens**. The distinction matters and is the whole point of this section: a token is a value the design system may tune as it learns — a colour, a radius, a duration. An invariant is a physical law of the layout. Tokens evolve across the phase; **invariants do not change without an explicit decision recorded here**, because they are the properties that make 17 independently-migrated screens feel like one application.

If a screen appears to need a different value, that is a finding, not a local override.

| # | Invariant | Value | Why it is frozen |
|---|---|---|---|
| **I1** | Spacing base unit | **4px**, with the fixed step set `0 · 1 · 2 · 3 · 4 · 6 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128` | Every margin, padding, and gap in the app resolves to a step. One off-scale value anywhere is the beginning of drift. No arbitrary spacing values (AC4). |
| **I2** | Breakpoints | `md` 768 · `lg` 1024 · `xl` 1280 · `2xl` 1536, mobile-first `min-width` only | The four validated widths (375/768/1024/1440) are anchored to these. Introducing a fifth breakpoint to solve one screen's problem breaks the responsive contract everywhere else. |
| **I3** | Primary sidebar width | **15rem / 240px** expanded. Below `md` it is a drawer, never a narrow rail. | There is no collapsed-rail state in Phase 09 — deliberately. Twelve destinations with labels do not survive icon-only collapse, and adding a collapsed mode means persisting its state and designing every nav item twice. |
| **I4** | Secondary filter rail width | **14rem / 224px**; right-hand context column **20rem / 320px**. Both become drawers below `lg`. | Secrets, Documents, and Prompt Studio must present the same rail geometry, or the app reads as three applications. |
| **I5** | Topbar height | **3.5rem / 56px**, owned solely by `AppShell` via `--shell-topbar-h` | No page may recompute shell geometry. This is the invariant that retires all three `calc(100dvh − …)` hacks. |
| **I6** | Data row height | **40px** desktop, **48px** at mobile touch widths | The rhythm shared by all seven data surfaces. Density is expressed through type scale and rule weight, never by shrinking rows below 40px. |
| **I7** | Minimum touch target | **44 × 44px** below `md` | WCAG floor. Never traded away for density. |
| **I8** | Maximum readable measure | **68ch** for long-form prose (Documents editor, Knowledge excerpts) | Long-form content does not stretch to the viewport at any width, including 1440+. |
| **I9** | Form column width | **32rem / 512px** max for a single-column form | Settings, auth screens, and dialog forms share one measure. |
| **I10** | Dialog width tiers | **sm 24rem** (confirm) · **md 32rem** (single-purpose form) · **lg 42rem** (multi-section form) · **xl 56rem** (content/preview). Full-width sheet below `md`. | Four tiers, chosen per purpose. A dialog with a bespoke width is the single most common source of visual inconsistency in a redesign. |
| **I11** | Control heights | **sm 28px · default 32px · lg 36px** | Buttons, inputs, and selects on one line share a height, so toolbars align without per-toolbar correction. |
| **I12** | Elevation usage | Shadows only on true overlays — dialog, popover, drawer, toast. **Never** on a card, panel, list row, or tool container. | The Rams "borders over shadows" rule, stated as a hard constraint because it is the first thing that erodes under per-screen judgement. |

**I10 and I11 are new** and are added to `DESIGN_TOKENS.css` Layer 3 by T1; the other ten are already expressed there. All twelve are re-checked at T30 and are covered by AC56.

## 1. The shell

```
AppShell  (grid; owns --shell-topbar-h; owns scroll containment)
├── Sidebar            md+ only, --shell-rail-w
│   ├── Brand
│   ├── Group: Workspace   Workbench · Projects
│   ├── Group: Library     Secrets · Notes · Documents · Knowledge
│   ├── Group: Build       Prompt Studio · Model Playground · Project Init
│   ├── Group: Tools       Converter · Developer Toolkit
│   ├── ─── divider ───
│   └── Settings           (utility)
├── Topbar             --shell-topbar-h
│   ├── MobileNav trigger  (below md)
│   ├── Breadcrumb slot    (populated on /projects/[id] only)
│   ├── Search trigger     → opens ⌘K palette
│   └── Lock
└── main               the ONLY scroll container
    └── {route}
```

Three rules that the current shell does not enforce and this one does:

1. **`main` is the only scroll container.** Pages never own viewport-height math. This retires `h-[calc(100dvh-3.5rem)]` (Documents, Prompt Studio) and `calc(100dvh - 7.5rem)` (Notes board).
2. **`PageHeader` is not optional.** All 17 routes use it, including Documents and Prompt Studio, which currently bypass it.
3. **Page padding comes from `--shell-page-pad-x`,** not from `p-4 md:p-6` re-declared in eleven files.

### 1.1 Sidebar item anatomy

Rams: the active state is a **left rule plus a weight change**, not a filled pill. Colour marks state; it does not decorate.

| State | Treatment |
|---|---|
| Default | `--sidebar-foreground` at 70%, icon at 50%, `--font-weight-normal` |
| Hover | Foreground to 100%, background `--sidebar-accent` at low alpha, `--duration-fast` |
| Active | 2px left rule in `--sidebar-primary`; label `--font-weight-medium`; icon at `--sidebar-primary` |
| Focus | `--ring` outline, 2px offset — never suppressed by hover |

Group labels use `.label-structural` (uppercase, `--letter-spacing-wide`, `--font-size-2xs`, `--muted-foreground`) and are `role="presentation"` labels on `<nav aria-label="…">` sections, not headings — they title a landmark, not document content.

**Active-route matching is preserved exactly:** `href === "/" ? pathname === "/" : pathname.startsWith(href)`. This is subtly correct today (it makes `/projects/[id]` highlight Projects) and must not be "simplified".

### 1.2 Topbar

Search trigger keeps its current affordance — a bordered field-shaped button showing `⌘K` — because it teaches the shortcut. Below `md` it collapses to an icon button. Lock keeps its mutation and its `router.replace("/unlock")` on success.

### 1.3 Command palette

| Group | Content |
|---|---|
| Navigate | All 12 destinations, with their `shortcut` letters now **bound**, not just displayed |
| Secrets / Notes / Documents | Live results once the query exceeds 1 character |
| — | **"View all results" → `/search?q=…`** (new) |
| Session | Lock Forge |

Deep-link targets are unchanged: `/secrets?open=<id>`, `/notes?open=<id>`, `/documents?open=<id>`.

## 2. Two typographic registers

The Rams/Swiss seam is exactly two utilities, defined once in `DESIGN_TOKENS.css`. Everything not listed here is Rams by default.

| Register | Applies to | Treatment |
|---|---|---|
| **Rams** (default) | Shell, page headers, forms, dialogs, tool cards, settings, auth | Single family, tight letterspacing on headings, generous body line-height, borders over shadows, one accent used only for state |
| **Swiss** (`.label-structural`, `.data-primary`, `.data-meta`) | The seven data surfaces: Secrets, Search results, Knowledge results, Ingest jobs, project scoped lists, generation history, run history | Rules as structure, scale contrast between title and metadata, uppercase letterspaced column labels, tabular numerals, zero shadows |

Swiss is a **treatment inside Rams containers**. It never introduces its own container, spacing, or color decisions.

## 3. Screen architectures

Each screen below states its primary goal, its layout, and its full state lifecycle. "Preserve" lines are contractual — they are re-tested in [`08_ACCEPTANCE.md`](08_ACCEPTANCE.md).

### 3.1 Workbench `/`

**Goal:** get back to work in one click. **Layout:** `PageHeader` (actions: customize toggle; in customize mode also Manage pinned tools + Reset) over a responsive panel grid — 1 col / 2 col at `md` / 3 col at `xl`.

Panels ranked: Pinned tools → Quick actions → Recent activity → Recent notes → System status. Panel cards lose their shadow and gain a rule-bounded header, per Rams.

- **Loading** — panel-shaped skeletons at panel dimensions, no layout shift.
- **Empty** (no visible panels) — `WorkbenchEmptyState` with a single path into customize mode.
- **Error** — per-panel via generalized `panel-error-boundary`; a failed panel never blanks the grid.
- **Customize** — reorder affordances appear; focus moves to the first meaningful control on entry and returns to the trigger on exit.

> **Preserve:** drag *and keyboard* reorder; the optimistic layout mutation with rollback; the rule that unregistered panel types survive unrelated user actions; `?new=1` quick-action deep links into Secrets/Notes/Projects.

### 3.2 Secrets `/secrets` — *reference implementation of the Swiss data surface*

**Goal:** find and open a secret fast. **Layout:** `PageHeader` (action: New secret) → `Toolbar` (`SearchField` + `ProjectPicker`) → `FilterRail` (folders, tags) + `DataList`.

Row: favourite/type icon · name (`.data-primary`) · tags · type badge · relative time (`.data-meta`, tabular). Rules between rows, not a card per row.

- **Loading** — row-height skeletons matching `--row-height`.
- **Empty** — `EmptyState` with New secret.
- **Filtered-empty** — distinct copy naming the active filters, with a clear-filters action. *(New — currently indistinguishable from truly-empty.)*
- **Error** — `ErrorState`, inline, retryable.
- **Detail** — `SecretDetailSheet` over the list, driven by `?open=`.
- **Destructive** — reveal/copy keep their explicit confirmation feedback; delete goes through `ConfirmDialog`.

> **Preserve:** `?open=`, `?project_id=`, `?new=`; server-side `q`/folder/tag/project filtering; the edit flow's `getSecret(id, true)` reveal call; `onSaved` → `router.push('/secrets?open=<id>')`.

**Responsive:** rail → drawer below `lg`; tags and timestamp drop below `sm` rather than truncating; rows reach `--row-height-comfy`.

### 3.3 Knowledge Hub `/knowledge`

**Goal:** browse, filter, tag, and link notes and documents. **Layout:** `PageHeader` → filter bar → `DataList`.

Copy is clarified so `?q=` reads as *a filter within the Hub*, not global search — this is the UI half of the [ADR-0016](../../decisions/0016-grouped-navigation-and-search-surface-consolidation.md) resolution. Truncation becomes a first-class element (`"Showing 100 of 340"` as a visible row, not header microcopy).

- **Loading / Empty / Filtered-empty / Error** — all four distinct; error retryable via the existing `onRetry`.

> **Preserve:** all four URL filters including repeatable `tag_id`; `router.replace` semantics; the `truncated`/`total` contract; tag and link panels.

### 3.4 Documents `/documents`

**Goal:** write. The editor gets the most space at every width.

**Layout:** `PageHeader` (**newly adopted**) → `FilterRail` (list + search + project) + editor pane. Editor toolbar is grouped by consequence: title · project · pin · tags/links · export · **│** · delete.

- **No selection** — `EmptyState` with New document.
- **Loading / Error** — skeleton, then `ErrorState`.
- **Saving** — an explicit, quiet saved/saving indicator. *(New — autosave is currently silent, so the user has no confirmation their work persisted.)*
- **Destructive** — delete routes through `ConfirmDialog` from **both** the toolbar and every rail row. *(Fixes the silent delete.)*

> **Preserve:** the 600ms debounced autosave and its patch shape; export menu; pin toggle; tag/link popover sourcing from the Hub list; `?open=`, `?project_id=`.

**Responsive:** below `lg`, rail and editor are single-pane with a back affordance — the Prompt Studio pattern.

### 3.5 Search results `/search`

**Goal:** see the complete result set for a query. **Layout:** `PageHeader` → `SearchField` (autofocus) → grouped `DataList` (Secrets / Notes / Documents).

- **Idle** (<2 chars) — `EmptyState` explaining the threshold.
- **Loading / Empty / Error** — `ErrorState` for errors, correcting today's semantically wrong use of `EmptyState` for a failure.

> **Preserve:** `?q=` sync via `router.replace`; the 2-character threshold; **the full secrets + notes + documents scope**.

### 3.6 Notes `/notes`

**Goal:** capture and arrange. **Layout:** `PageHeader` (Archived toggle, New note) → `Toolbar` (`SearchField`, `ProjectPicker`) → board.

- **Empty / Loading / Error** — standard treatments.
- **Destructive** — note delete routes through `ConfirmDialog`. *(Fixes the silent delete.)*

> **Preserve:** dnd-kit drag *and keyboard* interaction; resize; Markdown rendering; colour assignment; archive toggle; `?open=`, `?project_id=`, `?new=`.

**Responsive:** the board keeps horizontal pan rather than reflowing — a spatial canvas that reflows is no longer a spatial canvas.

### 3.7 Projects `/projects` and `/projects/[id]`

**List:** `PageHeader` (Archived toggle, New project) → card grid, 1/2/3 col.
**Detail:** `PageHeader` (name, description, Edit · Archive · **│** · Delete) → main column of scoped `DataList`s (Secrets, Notes, Documents) + `--shell-detail-rail-w` column (AI config, quick run). Breadcrumb `Projects / {name}` populates the topbar slot.

- **Loading / Not-found / Error** — not-found keeps its `EmptyState` and back-to-projects path.

> **Preserve:** archive/unarchive; delete via the existing dedicated dialog with its unscope-not-cascade semantics; "View all" links to `/{feature}?project_id=`.

### 3.8 Prompt Studio `/prompt-studio`

**Layout:** `PageHeader` (**newly adopted**) → `FilterRail` (list, search, tags) + editor (body, variables, preview, version history).

> **Preserve:** the existing `lg`-breakpoint single-pane behavior and back affordance — **this is the reference pattern, do not regress it**; the `body` min-length-1 create workaround; duplicate/delete/restore flows; `?open=`.

### 3.9 Model Playground `/model-playground`

**Layout:** `PageHeader` → main column (provider list, prompt composer, result panel) + `--shell-detail-rail-w` history column with run history as `DataList`.

- **Running** — explicit in-flight state; long-running calls must never present as a frozen UI (`04_UI_GUIDELINES.md` §2).

> **Preserve:** credential create/delete flows and their confirmations exactly (ADR-0011 governs credential handling); run creation, selection, and deletion.

### 3.10 Converter `/converters`

**Layout:** `PageHeader` → `SectionHeading` "Text & Data" → `ToolCard` grid (9 tools, 1/2/3 col) → `SectionHeading` "Documents" → dropzone → job list as `DataList`.

- **Uploading / Processing / Complete / Failed** — the polling states get explicit treatments.

> **Preserve:** `CONVERTER_TOOL_PROVIDERS` composition; the 800ms `refetchInterval` while processing; the preview sheet; `/ingest` redirect.

### 3.11 Developer Toolkit `/developer-toolkit`

**Layout:** `PageHeader` → top-level tabs (Generators / Crypto / Utilities), with Crypto retaining its nested tab set.

> **Preserve — external contract:** `?tab=` values `generators|crypto|utilities` are the redirect targets for `/generators`, `/crypto`, `/utilities`. Tab switching stays `router.replace(..., { scroll: false })`. Unknown `?tab=` still falls back to `generators`. All 16 tools keep their current composition order.

### 3.12 Project Init `/project-init`

**Layout:** `PageHeader` → kind picker → form + file preview → `SectionHeading` "Recent generations" → `DataList`.

- **Catalog error** — currently a bare red paragraph with no retry; becomes a retryable `ErrorState`.
- **Destructive** — generation delete routes through `ConfirmDialog`. *(Fixes the silent delete.)*

### 3.13 Settings `/settings`

**Layout:** `PageHeader` → cards grouped by consequence: Appearance · About (reference) — then a divider — then Master password · Backup (consequential).

The destructive-import warning moves adjacent to the Import control rather than sitting below the card. The About card's Storage line renders once FR14's rewrite lands.

> **Preserve:** theme set + server sync; password change validation (≥8 chars); export filename format; import parse-error handling.

### 3.14 Setup `/setup` and Unlock `/unlock`

The only unauthenticated surfaces and the first thing a new user sees. Centered card on `--background`, brand mark, `--max-width-form`. Restyled to tokens; shadow reduced to `--elevation-2`.

> **Preserve:** `AuthGate` redirect logic entirely; unlock → `router.replace("/")`; inline error rendering; autofocus.

### 3.15 AuthGate loading

The full-screen spinner shown before every authenticated route. Retuned; must honour `prefers-reduced-motion`.

## 4. Responsive contract

| | 375 | 768 (`md`) | 1024 (`lg`) | 1440 (`xl`) |
|---|---|---|---|---|
| Primary nav | Drawer | Drawer | Rail | Rail |
| Filter rails | Drawer | Drawer | Inline | Inline |
| Master–detail | Single pane | Single pane | Split | Split |
| Tool / panel grids | 1 col | 2 col | 2 col | 3 col |
| Project cards | 1 col | 2 col | 3 col | 3 col |
| Data row height | `--row-height-comfy` | `--row-height` | `--row-height` | `--row-height` |
| Header actions | Overflow past 2 | Inline | Inline | Inline |
| Secrets row | Name + type only | + timestamp | + tags | full |

Mobile-first: base styles target 375px; every breakpoint is `min-width`.

## 5. Accessibility contract

Applies to every screen above; verified in T27.

- **Contrast** — WCAG 2.1 AA in both themes, measured against the budget at the foot of `DESIGN_TOKENS.css`.
- **Focus** — one `:focus-visible` treatment, 2px `--ring` at 2px offset, never suppressed by hover. Trapped in dialogs/sheets/drawers; restored to the trigger on close.
- **Names** — every icon-only control gets `aria-label`. `title` alone is not sufficient (38 buttons today; 3 compliant).
- **Semantics** — `nav`/`main`/`aside` landmarks with labels; ordered headings; lists as `<ul>`/`<table>`, not `<div>` stacks.
- **Forms** — inline errors associated via `aria-describedby`; `aria-invalid` on failed fields; never an alert dialog for validation.
- **Live regions** — save state, copy confirmation, and run progress announced politely.
- **Motion** — `prefers-reduced-motion` disables transitions globally.
- **Targets** — ≥44×44px below `md`.
- **Colour** — never the sole signal; status always pairs colour with text or icon.
