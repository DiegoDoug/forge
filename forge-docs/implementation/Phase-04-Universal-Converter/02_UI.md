## 1. Screens / views

One screen, replacing two existing ones:

- **`/converters`** (URL unchanged from today) — the unified Universal Converter page. Two stacked sections:
  - **Text & Data** — the existing grid of nine `ToolCard` widgets (JSON, YAML, XML, CSV, Regex, URL Encode, Unicode Inspector, Cron, Timestamp, Diff), moved here unmodified from today's `/converters` page.
  - **Documents** — the existing Ingest workflow (`Dropzone` → `JobList` → `PreviewSheet`), moved here unmodified from today's `/ingest` page.

  Rationale for keeping both sections on one page rather than tabs: both are already independent, self-contained widgets/workflows today (no shared state to switch between), and the current Converters page already renders nine independent tools in one scrolling grid — the Documents section is simply one more grouped area in that same pattern, not a new UI paradigm. A future phase adding new providers can promote this to tabs if the page grows unwieldy; not needed at today's two-section scale (per [`01_PRODUCT_PRINCIPLES.md`](../../01_PRODUCT_PRINCIPLES.md), don't build for a hypothetical future scale).

- **`/ingest`** — becomes a redirect to `/converters`, per [`01_SPEC.md`](01_SPEC.md) §3 requirement 2. Not a real screen after this phase ships.

## 2. Navigation

`frontend/lib/nav-registry.ts` currently has two entries:

```ts
{ title: "Converters", href: "/converters", icon: Repeat, description: "JSON, YAML, regex, diff", shortcut: "O" },
{ title: "Ingest", href: "/ingest", icon: FileInput, description: "Documents → Markdown", shortcut: "I" },
```

These are replaced by one entry:

```ts
{ title: "Converter", href: "/converters", icon: Repeat, description: "Text, data & document conversion", shortcut: "O" },
```

- Keeps the `Repeat` icon and `O` shortcut (already muscle-memory for existing users of the Converters page); `FileInput` and shortcut `I` are freed up.
- Singular "Converter" (not "Converters") to name the unified surface as one thing, matching the phase's own name — TODO: confirm exact label wording with the project owner; this is a naming proposal, not a load-bearing decision.
- The command palette (`cmdk`) reads from the same `NAV_ITEMS` registry, so this single change updates both surfaces per [`04_UI_GUIDELINES.md`](../../04_UI_GUIDELINES.md) §2 ("every feature page is reachable from the sidebar and the command palette").

## 3. States

**Text & Data section** — unchanged from today; each `ToolCard` already defines its own empty/populated/error states inline (e.g. JSON tool shows nothing until run, then output or an inline error message). No new state work required — these components are moved, not rebuilt.

**Documents section** — unchanged from today's Ingest page:
- Empty: `Dropzone` alone, no job yet.
- Loading: `JobList` with per-file "processing" status and a progress bar, polled every 800ms while any file is processing (existing `refetchInterval` behavior).
- Error: per-file error state already shown inline in `JobList` (task.error message); a whole-job failure (all files errored) is representable today and unchanged.
- Populated: `JobList` showing done/error per file, with preview/download/save-to-notes actions.

No new state design work is required by this phase — both sections' state handling is inherited unmodified. This is called out explicitly (rather than left silent) because [`04_UI_GUIDELINES.md`](../../04_UI_GUIDELINES.md) §5 requires every list-based feature's phase doc to state this, even when the answer is "already covered."

## 4. Responsive behavior

Unchanged from today: the Converters grid already collapses from `md:grid-cols-2` to a single column below the `md` breakpoint; the Ingest dropzone/job-list already stack in a single `flex-col` column at every width. Stacking two already-responsive sections vertically on one page does not introduce a new responsive-design problem.

## 5. Accessibility

Unchanged from today — no new interactive patterns are introduced (no new drag-and-drop, no new keyboard-only flows). The one net-new interactive element is the single consolidated nav entry, which reuses the existing sidebar/command-palette keyboard navigation path unmodified.
